## Notes that matter for the audit
- **Conflict of interest.** TabCausal's authors are exactly CausalArena's authors (Li, Liu, Wang, Ye). Compare https://arxiv.org/html/2605.31156v1 with https://arxiv.org/abs/2609.11897. CausalArena's baseline conventions also match TabCausal's `baselines/` code (see DOM-07a). Note this when we cite TabCausal's leaderboard rank.
- **Order sensitivity.**
  - Only AVICI, FoundCause and Arrow state variable-permutation equivariance in their papers.
  - SEA uses positional embeddings, so its output can depend on column order.
  - CDFM, CauScale and TabCausal are unverified.
  - CausalArena columns appear to follow a topological `node_order` (DOM-07a(iv)). So any order-sensitive model may benefit from that leakage. A **column-permutation re-run** is the control.
- **Licence blockers for redistribution.** TabCausal, SEA and the CauScale code have no licence, and Arrow has no release. Running them locally for evaluation is a different question from redistributing them; flag it to the mentor.
- **Practical CPU set for our machine:** AVICI, CDFM, FoundCause, TabCausal. SEA needs a GPU for aggregation. CauScale is NV.
